# 用户视角评测与测试维度

这份矩阵把“功能存在”转换成“用户能否安全、快速、可理解地完成任务”。每个模块在进入真实写入前都必须通过 P0-P2 三档验收。

| 维度 | 用户问题 | 第一版验收标准 | 自动化方式 |
| --- | --- | --- | --- |
| 首次上手 | 我打开后知道下一步做什么吗？ | 30 秒内看到设备状态、权限缺口和 dry-run 提示 | `MainActivityTest.firstOpenShowsHomeAndServiceControl` + 人工走查 |
| 权限透明 | 为什么要授权？不给会怎样？ | 每项权限说明用途、风险、跳转入口；拒绝后仍可浏览只读内容 | UI 测试 + 权限拒绝场景 |
| 后端可理解 | root/ADB/Shizuku 有什么区别？ | 展示后端状态、能力范围和当前实际使用后端 | 状态模型单测 |
| 安全可逆 | 点了调节能恢复吗？ | 执行前显示变更摘要；失败自动恢复；日志可查 | 事务/回滚单测 + 故障注入 |
| 成功反馈 | 我知道是否真的生效了吗？ | 显示 supported/applied/failed/rollback，避免只提示“完成” | 状态机单测 |
| 场景可控 | 场景何时触发、影响哪些应用？ | 包名、优先级、触发器、当前生效场景均可见 | 场景选择器单测 + UI 测试 |
| 性能负担 | 这个工具会不会耗电？ | 轮询间隔可见；服务可停止；无权限时不空转 | 轮询去重测试 + 电量人工测试 |
| 数据可靠 | 重启后配置还在吗？ | 场景和日志可恢复；损坏数据安全降级 | 持久化读写测试 |
| 可访问性 | 小屏、深色模式、字体放大能用吗？ | 触控目标达标、内容描述完整、布局不截断 | Accessibility Scanner + 多尺寸截图 |
| 兼容性 | 我的 Android/厂商能用吗？ | 不支持能力明确标注，不把“未探测”当成“不支持” | API 23/29/35 真机矩阵 |
| 离线可用 | 没网络还能用吗？ | 设备读取、场景编辑、日志查看不依赖网络 | 断网测试 |
| 隐私 | 数据会上传吗？ | 第一版不上传应用列表、遥测和日志；文案明确说明 | 网络拦截检查 |
| 指标可解释性 | 这个 FPS 数字代表什么？ | 明确显示采集范围（当前窗口）、采样窗口、刷新率上限、P95 与卡顿阈值，不把估算值包装成系统全局值 | 指标边界单测 + 设备人工对照 |
| 采集生命周期 | 开始后会不会一直耗电？ | 开始/结束按钮状态互斥；页面离开、服务停止时释放 FrameMetrics listener 和线程 | 生命周期单测 + LeakCanary/人工观察 |
| UI 导航 | 我能从首页进入目标模块吗？ | M3/M8 入口可点击，目标页关键操作可见且无空白页 | `MainActivityTest` 模块导航用例 |

## 必测用户路径

1. 首次打开 → 查看设备能力 → 发现 Usage Stats 未授权 → 跳转设置 → 返回后状态刷新。
2. 应用列表 → 搜索包名 → 创建场景 → 绑定应用 → 保存 → 重启应用 → 场景仍存在。
3. 启动场景服务 → 前台应用变化 → 选择最高优先级场景 → 查看任务日志 → 停止服务。
4. 只读后端不可用 → 页面仍可浏览 → 不出现可点击的危险写入按钮。
5. 场景执行中途失败 → 显示失败原因 → 尝试 restore → 日志记录完整链路。

## 发布门槛

- P0：权限透明、安全可逆、成功反馈、数据不丢失必须通过。
- P1：首次上手、场景可控、性能负担、兼容性必须通过主流设备。
- P2：深色/无障碍/离线体验在正式发布前完成，不得阻塞内部测试版。
