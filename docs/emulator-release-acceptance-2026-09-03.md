## 用户路径走查

1. 首次启动时，总览在首屏明确显示“自动化尚未就绪”和唯一下一步“去授权”。点击后进入 Android 的 Usage Access 页面；授予后返回，页面自动变为“设备已就绪”。
2. 预览模式下启动自动化后，系统中存在 `SceneTriggerService` 前台服务与持续通知；点击停止后服务消失，页面恢复为可启动状态。
3. 从应用列表选择系统设置，可直接进入带应用对象的场景链路；预演后启用，只产生预览事件，不创建真实恢复 journal。
4. Android 15 上进行一段 FPS 会话后，页面生成平均渲染 FPS、最低/最高、P95 帧耗时和卡顿摘要；重进监控页历史仍在，CSV 会打开 Android 系统分享面板。
5. Root 与 Shizuku 在虚拟机不可用时保持不可选择，并分别解释“未发现可执行 su”和“Shizuku 服务未运行”，没有静默切换执行方式。

## 正式发布阻断项

以下任一项未完成前，不得把版本标注为“全部功能正式可用”：

1. 在用户明确授权的 KSU/Magisk 真机上验证应用 UID 的授权、拒绝、撤权与 Root 进程超时处理。
2. 在绑定报告所对应的 SM8750 / `sun` / 6+2 设备上，对实际展开路由逐项完成原值快照、写入、读回、离场恢复、进程中断和恢复不完整锁定。
3. 真机验证线程 cpuset/affinity/RR/nice、动态 limiter、Gesture watcher 的 PID/start ticks、owner、健康检查与 CAS 恢复；`ddr_boost=true` 和非空 Gesture exit 继续阻断。
4. 在安装并授权 Shizuku 的 Android 7+ 真机上验证 UserService 连接、读写、断连和撤权恢复；Root-only worker 在 Shizuku 下必须继续拒绝。
5. 用 TalkBack 做完整焦点顺序、控件朗读、200% 字体和实际小屏人工走查；当前仅完成语义树、48 dp 触控边界、大字体、深浅色和最低系统自动化检查。
6. 配置正式签名、版本升级策略和发布渠道；若上 Google Play，完成 `specialUse` 前台服务与 `QUERY_ALL_PACKAGES` 的政策申报。
