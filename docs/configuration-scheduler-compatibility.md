# 配置调度兼容与原生实现边界

## 目标

栖境要复现的是“配置产生的可观察行为”，不是旧应用的页面、目录、脚本或数据层。目标链路为：

`选择四档模式 → 编译设备目标 → 建立原值快照 → 应用并读回 → 前台应用命中 → 调整线程归属 → 离场恢复`

用户提供的 KSU 包属于配置替换模块，本身不是调度执行器。它包含多套设备配置和线程规则，但没有独立完成配置编译、前台应用判断、线程持续扫描、当前模式可信读回或失败恢复。因此，单独刷入该包不能让栖境安全获得同等控制能力。

## 已确认的旧行为规格

- 全局意图包含省电、均衡、性能、极速四档，并区分活动与非活动状态。
- 配置通过别名、预设和宏展开为 CPU、GPU、cpuset、调度器及厂商节点操作。
- 应用规则按前台包名选择配置；线程规则按进程、线程名和通配前缀分配 CPU 集合，并可附带调度优先级意图。
- 常驻执行器持续观察线程创建和前台切换，而不是只在点击按钮时执行一次。
- 部分配置会修改核心在线状态、GPU、WALT、厂商私有节点和系统 cpuset；栖境只在匹配变体中把已声明路径编译为类型化事务，仍需在匹配设备逐项真机验收。

以上结论只作为 clean-room 行为规格，不把旧文件、旧脚本或旧产品结构复制进栖境。

## 两层实现

### 1. 配置模块桥接（保留兼容）

用于识别外部配置模块并提供四档模式兼容。模块身份只能证明“安装了什么”，不能证明“成功应用了什么”。真实控制必须同时具备：

1. 固定桥接契约标识 `qijing-scheduler-bridge-v1`；
2. 固定、无调用方路径参数的模式切换入口；
3. 可读取的当前模式；
4. 桥接执行器内部对全部声明目标完成写后读回，仅在验证通过后更新当前模式；
5. 失败时恢复本次已修改目标，并返回“未写入 / 已恢复 / 恢复不完整”之一。

当前提供的 ZIP 不包含这套桥接契约，因此不能通过“配置调度器”桥接入口直接切换。现在可改用下述栖境原生引擎导入其中的声明式配置；原包脚本、卸载逻辑和应用数据清理仍不会执行。

### 2. 栖境原生调度引擎

当前实现不依赖外部应用，包含：

- **设备包检查器**：匹配 SoC、CPU 拓扑、内核节点和配置版本，任何一项不符即阻止加载；
- **类型化配置编译器**：只接受已注册能力，不接受任意 Shell；宏展开后仍逐项经过能力、值域和路径策略；
- **事务执行器**：逐节点快照、持久 journal、写后读回、逆序恢复；
- **线程规则引擎**：包名、线程名精确/前缀匹配、CPU 集合校验、冲突优先级和默认归属；
- **Root 常驻执行器**：监听前台、交互状态与新线程，身份不变时避免重复写入；需要重新编排时先恢复当前事务，退出和异常重启均进入 journal 恢复；
- **栖境动态 limiter**：对导入配置中的 `margins / excludes / prefer` 建立有所有权的 Root worker，按 CPU 负载生成频率目标，升频立即、降频延迟，逐次写前检查最后写入值并读回；这是公开、可审计的“栖境语义”，不宣称复刻旧私有 daemon 算法；
- **手势调度 watcher**：仅实现真实包中已出现的 BTN_TOUCH DOWN 写入、UP 恢复语义；每次按压单独快照，异常或第三方值冲突时停止继续覆盖；非空 exit 和未实现的事件协议保持阻断；
- **托管进程健康检查**：自动化定时验证 contract、PID、启动时钟和进程命令行；fault、stale、错误 owner 或读取失败时不自动重启，而是先恢复活动事务并停止自动化；
- **证据接口**：向 UI 提供命中规则、实际线程数、应用前后值、验证结果和恢复状态。

Shizuku 不应被默认宣传为可控制其他应用线程；只有设备实测证明权限与 SELinux 允许时才开放。线程级能力第一阶段只考虑显式 Root。

## 完成标准

“功能相同”不能以按钮存在或命令退出码为准，至少需要通过：

1. 四档模式分别显示编译后的实际目标，并能从原值恢复；
2. 前台应用命中后，实际线程归属与规则一致，新建线程能在限定时间内被纳入；
3. 多场景冲突结果可预演且与运行结果一致；
4. 任意一步失败都能区分未写入、已恢复和恢复不完整；
5. 杀进程、撤销 Root、重启和应用离场测试后，不遗留未记录的系统状态；
6. 在匹配的 8E/8E5 测试设备完成逐项真机验收，MIX 2S 不作为执行设备。

## 实施顺序

1. 已完成：外部配置模块的 fail-closed 身份与桥接契约适配。
2. 已完成：安全 ZIP 导入、设备变体匹配、profile 全宏编译、应用导入片段和私有持久化。
3. 已完成：配置操作到类型化设备命令的绑定，以及与预演、快照、journal、读回、回滚的统一接入。
4. 已完成：Root 线程快照、规则规划、cpuset/affinity/RR/nice、新线程重新纳入和 active/inactive 场景生命周期。
5. 已完成：动态 limiter 和 Gesture Boost 的 Root 托管进程、内部快照/CAS、进程身份校验、健康检查与异常恢复。
6. 待完成：在匹配 8E/8E5 测试机逐项授权验收；在此之前 UI 只能陈述“可预演/未真机验收”，不能把离线通过写成真机已应用。
