## 早期能力核对结果

早期静态能力中的多后端执行、应用场景、CPU/内存调节、FPS session 和应用管理均已在新代码中建立对应契约或状态层。脚本运行时、在线内容、厂商专用写入、云端账户、电池/显示/OTA 等根据第一版范围明确排除，不属于遗漏。

当前实现不迁移旧数据，也不使用旧版命名、脚本或公开描述。能力是否完成只以本工程的代码、测试和真机验收证据为准。

## 当前发布阻塞项

1. C0 已有 Root/Shizuku Android 后端和固定白名单，但尚未完成真机授权、写入、读回与恢复验收，不能标为发布可用。
2. C1 已完成进程内离场/切换/停止恢复核心；仍缺真机验证和进程被系统杀死后的持久化恢复。
3. M4/M5 仍是只读状态和参数契约，不能宣称“调节已完成”。
4. M8 当前窗口采集、历史和 CSV 已实现，但尚未经过真机执行；外部应用 FPS 不属于现有采集能力。
5. M2 需要根据最终分发渠道确定 Android 11+ 应用可见性方案。
6. Compose UI 用例仅完成编译，尚未在真机或模拟器运行。

后端、恢复生命周期和真机测试的完成标准见 [后端与恢复验收标准](backend-acceptance.md)。

## 后续实施顺序

1. 在 Root 与 Shizuku 真机上验证授权、拒绝、撤销、目标不可写、读回不一致和后端失效路径。
2. 持久化未完成事务与原始快照，补齐进程被杀后的恢复提示和处理。
3. 在 M4/M5 中只开放当前设备与当前后端真机确认支持的控件；ZRAM 在恢复验收前保持关闭。
4. 运行真机矩阵与 Compose UI 测试，修复兼容性问题后再更新完成状态。
